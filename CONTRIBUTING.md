# Contributing

Contributions are welcome for:

- specification corrections;
- ambiguous or conflicting normative language;
- new conformance fixtures;
- independent implementation reports;
- interoperability mappings;
- privacy and disclosure edge cases;
- federation and custody edge cases;
- preservation and challenge-retention cases.

## Change proposal format

A proposal should include:

1. problem statement;
2. affected RFC(s);
3. proposed normative text;
4. machine-readable impact;
5. compatibility analysis;
6. privacy and security impact;
7. conformance-fixture impact;
8. migration path if incompatible.

Do not use a documentation edit to silently change normative semantics.
